## 1. Phase 0 现场测试（最高优先级）

### 1.1 前置

- 一个专门的测试抖音账号
- 两个可控测试群聊（不要使用真实家庭群/工作群）
- 两个测试账号，用于分别分享不同作品
- 一台运行 Douyin Vault 的 Mac
- 至少一个作品在缓存后可以被作者删除或设为私密，用于失效测试
- 一个可随时断网的网络环境

### 1.2 现场 harness

```bash
pnpm live:preflight
RUN_LIVE_TESTS=1 \
RUN_LIVE_DATA_DIR=./data/live-check \
LIVE_DURATION_SECONDS=900 \
LIVE_DOWNLOAD=1 \
pnpm test:live
```

harness 会：

- 显示二维码图片路径，扫码登录
- 打印账号、群列表、历史取样
- 对收到的作品卡调用 `getAccess()`，报告 `canDownload` / `canShare` / 媒体数
- 可选下载第一个可访问视频到 `data/live-check/downloads/`
- 结束或 Ctrl+C 后写入 `docs/acceptance-report.local.md`
- **不自动把任何用例标记为通过**

结果文件包含群名/群 ID 与统计，不要提交到 Git。

### 1.4 现场步骤

1. 先运行 `pnpm live:preflight`，确认 ffmpeg/ffprobe/yt-dlp 与目录可写。
2. 运行 harness，扫码登录。记录二维码出现与登录成功。
3. 在两个受控群分别发送：
   - 一条正常视频分享；
   - 同一作品重复分享；
   - 同一作品在另一个群分享；
   - 一条普通文本；
   - 一张图片；
   - 一条已失效/删除作品；
   - 一条群内原生视频。
4. 观察 harness 输出：群消息、作品卡、`getAccess()`、下载文件。
5. 复制 harness 的 Session 数据目录不变，重启 harness，确认免扫码上线。
6. 在下载过程中断开网络 30–60 秒，观察重连与历史补拉。
7. 在 Douyin Vault 管理界面确认：
   - 两个群的状态与来源数；
   - 视频只出现一次但来源两条；
   - 失败记录与错误码可见；
   - 普通文本与图片没有视频记录；
   - 本地视频可拖动播放；
   - 重启后账户、群、队列恢复。
8. 缓存成功后删除原作品（或让测试账号设私密），确认本地仍可播放。
9. 打开 `docs/acceptance-report.local.md`，逐项勾选并补充失败日志、复现条件、已知限制。
10. 如果任何关键项失败，**停止**，不要进入日常使用；修复或改用备用适配器后重新验收。

## 2. 产品功能验收

## 3. 运行目标

| 指标 | 目标 | 验证 |
|---|---|---|
| 消息进入主服务后创建任务 | 正常负载 5 秒内 | 本地集成 |
| 重复消息 | 不产生重复视频文件 | 集成 |
| 服务崩溃 | 已确认完成视频不丢失 | 集成 + 恢复逻辑 |
| 单任务失败 | 不影响其他任务 | 集成/Worker |
| 群同步缺口 | 必须记录 | 单元/同步审计 |
| 本地播放 | 支持拖动与续播 | E2E + Range |
| 敏感凭据 | 不进入普通前端/日志 | 代码审查 + 安全用例 |

5 秒是内部处理目标，不是抖音消息到达延迟的承诺。

## 5. 未通过时怎么办

| 失败点 | 下一步 |
|---|---|
| douyin-im 登录失败 | 保留 SDK 版本与脱敏日志，尝试其 demo；检查验证码/设备环境 |
| 能登录但收不到群消息 | 用 SDK demo 验证群事件；不要继续开发下载层 |
| 能收消息但无 workId | 检查消息类型与 `event.work`；记录原始卡片脱敏样本 |
| `getAccess()` 无媒体 | 检查账号权限、作品状态、`canDownload`；尝试作品 ID + 下载 API |
| 下载 API 不可用 | 检查 v5 task/API key 或 v4 endpoint；确认文件归主服务所有 |
| yt-dlp 403/Cookie | 不无限重试；先确认 IM 会话可解析直链，再配置下载 API |
| 补拉不完整 | 记录 gap；缩小群数量/频率；不要宣称完整 |
| Playwright 选择器失效 | 视为实验方案；优先修复主适配器 |

所有失败都要在 UI/任务/同步审计中可见，不允许“看起来运行正常”。
